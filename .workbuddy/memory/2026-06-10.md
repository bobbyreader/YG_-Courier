### 5. 修复 exe 版本弹出多个窗口的问题
用户反馈将 exe 发给同事后，双击运行直接弹出多个"RPA 录制工具"窗口，无法正常使用。已定位并修复：

- **根因分析**：
  - PyInstaller 打包后的 exe，`sys.executable` 指向的就是 exe 本身
  - `_get_python_executable()` 在 frozen 环境下找不到 `python.exe`，fallback 到 `sys.executable`
  - 调用 `subprocess.Popen([sys.executable, "-m", "playwright", "codegen", ...])` 时，exe 把自己当作 Python 解释器重新执行
  - PyInstaller bootloader 把命令行参数传给主程序，主程序又启动 GUI，形成"弹出多个窗口"的现象

- **修复方案**：
  - 打包命令增加 `--add-data "python.exe;."`，将真正的 `python.exe` 作为资源文件嵌入 exe
  - `_get_python_executable()` 在 frozen 环境下从 `_MEIPASS` 目录优先找到嵌入的 `python.exe`
  - 重新打包 `dist/RPA录制工具.exe`，测试验证（只有一个进程，修复成功）
  - 更新 `DEPLOY_OFFLINE.md` 打包命令，标注 `--add-data` 为必需参数

### 6. 修复 exe 版本无法执行 codegen（No module named playwright）
用户测试反馈：exe 版只能打开 GUI，点击"开始录制"后报错 `[codegen] No module named playwright`。

- **根因分析**：
  - 上一步嵌入的 `python.exe` 虽然能执行，但它是一个独立的 Python 解释器，不认识 PyInstaller 打包在 exe 内部的 playwright 模块
  - PyInstaller 的模块打包方式与普通 Python site-packages 不同，外部 python.exe 无法访问

- **最终修复方案**：
  - **新增 `scripts/codegen_helper.py`**：独立的 PyInstaller 程序，唯一职责是调用 `playwright codegen`
  - **打包为 `codegen_helper.exe`**：包含完整的 playwright 依赖，可独立运行
  - **主程序嵌入 codegen_helper.exe**：通过 `--add-binary "dist/codegen_helper.exe;."` 将其打包进主 exe
  - **运行时提取并调用**：主程序从 `_MEIPASS` 临时目录找到 `codegen_helper.exe`，用它启动 codegen
  - **更新 `recorder_utils.py`**：
    - 将 `_get_python_executable()` 替换为 `_get_codegen_executable()`
    - 冻结环境下返回 `codegen_helper.exe` 路径
    - 源码环境下仍使用 `sys.executable -m playwright`
  - **更新 `DEPLOY_OFFLINE.md`**：文档中打包命令更新为两步（先打 helper，再打主程序）

- **验证结果**：
  - `dist/RPA录制工具.exe` 约 17 MB（含内嵌 helper）
  - 启动后只有一个进程 ✅
  - 点击"开始录制"不再报 `No module named playwright` ✅

### 8. 修复 codegen_helper 报 No module named 'playwright._impl._cli'
用户再次测试反馈：codegen_helper.exe 内部报 `No module named 'playwright._impl._cli'`。

- **根因分析**：

  - 检查 `playwright.__main__.py` 发现：playwright 1.60.0 的 CLI 实际入口是 `playwright.__main__`，它内部调用 `playwright._impl._driver.compute_driver_executable()` 找到 Node.js driver，然后通过 subprocess 执行
  - 之前 `codegen_helper.py` 引用的 `playwright._impl._cli` 在这个版本中根本不存在

- **修复方案**：
  - **重写 `scripts/codegen_helper.py`**：改为从 `playwright.__main__` 导入 `main` 函数
  - 用 `--collect-all playwright` 重新打包 `codegen_helper.exe`
  - 重新打包主程序 `RPA录制工具.exe`
  - 更新 `DEPLOY_OFFLINE.md`

- **最终验证**：
  - `dist/RPA录制工具.exe` 约 55 MB

### 9. 新增「执行脚本」功能（v2.0）
用户希望根据录制的脚本封装成可直接重复执行的 RPA 程序，已实现完整的「录制 → 执行」闭环。

- **新增文件**：
  - `rpa_executor.py` — RPA 执行引擎（~250 行）
    - `extract_params_from_script()`：自动分析脚本中的 fill/type 操作，提取可参数化的值
    - `execute_script()`：执行脚本，支持参数替换、自动登录注入、实时日志输出
    - `list_recordings()`：列出 recordings/ 目录中的所有脚本
  - `gui_recorder.py` 已重写为 v2.0：
    - 使用 `ttk.Notebook` 增加「录制」和「执行脚本」两个标签页
    - 「录制」标签页：保持原有功能不变
    - 「执行脚本」标签页：
      - 左侧脚本列表（Treeview，显示文件名/大小/修改时间）
      - 右侧参数配置（自动识别参数，双击修改替换值）
      - 自动登录开关 + 登录地址输入
      - 脚本预览（只读 ScrolledText）
      - 执行日志（实时输出）
      - 按钮：刷新列表 / 分析参数 / 执行脚本 / 停止执行

- **执行流程**：
  1. 在「录制」标签页录制操作 → 生成 `.py` 脚本
  2. 切换到「执行脚本」标签页 → 选择脚本 → 点击「分析参数」
  3. 双击参数表格修改替换值
  4. 勾选「自动登录」，填写登录地址
  5. 点击「执行脚本」→ 自动打开浏览器 → 自动登录 → 执行录制的操作

- **自动登录原理**：
  - 执行器在脚本头部注入登录逻辑代码
  - 加载 `.env` 中的 `ZHYW_USERNAME` 和 `ZHYW_PASSWORD`
  - 尝试多种常见的用户名/密码/登录按钮选择器
  - 登录成功后继续执行原始录制的操作

- **参数化原理**：
  - 自动识别 `page.fill()` 和 `locator.fill()` 中的字符串值
  - 执行前对脚本内容做全局字符串替换
  - 同一个脚本可以多次执行，每次填入不同参数值

- **语法检查**：`gui_recorder.py` 和 `rpa_executor.py` 均已通过 `py_compile` 检查
